## 1) Current custom domains attached
Verified via list_domains + check_domain_status:

- www.viciconsulting.ca — verified, provider cloudflare, ssl_status=active, ssl_validation_method=http, root_redirect_enabled=true, linked=true

There is NO tool available to the deployer agent to add/attach/detach a custom domain. That action is user-side only.

## 2) How attachment works + DNS records to add
Attachment is done by the USER in the Manage Publishing UI (Deployment Panel → Domains → "Link your Domain"). The agent cannot attach it directly. The user must:
  a. Add both saskstartupsolutions.ca and www.saskstartupsolutions.ca in Deployment Panel → Domains.
  b. Create the matching DNS records in their Cloudflare account.

Because the existing (working) domains use http validation with a CNAME to the platform default host, the new domain follows the same pattern. The CNAME target is the deployment's default host: `vici-registry-admin.emergent.host`.

DNS records to add in Cloudflare (match the working viciconsulting.ca setup):
- Type: CNAME | Name: www (www.saskstartupsolutions.ca) | Target: vici-registry-admin.emergent.host | Proxy status: DNS only (gray cloud)
- Type: CNAME | Name: @ / apex (saskstartupsolutions.ca) | Target: vici-registry-admin.emergent.host | Proxy status: DNS only (gray cloud)
  - Cloudflare supports CNAME-at-apex via CNAME flattening, so a CNAME on the root is fine.

Note on proxy status: use DNS only (gray cloud). The platform is itself Cloudflare-for-SaaS; proxying (orange cloud) from the user's own Cloudflare zone to another Cloudflare SaaS zone can interfere with custom-hostname validation and cert issuance. The existing viciconsulting.ca records resolve/link correctly with this http-validation pattern.

## 3) HTTPS/SSL provisioning
SSL is automatic once the domain is added in the panel AND the DNS record resolves. Validation method is http (same as the existing domains), so NO TXT record is required. After DNS propagates, Cloudflare-for-SaaS issues the certificate automatically; ssl_status will move from pending to active (usually minutes, can take longer while DNS propagates). No action beyond correct DNS + adding the domain in the panel.

## 4) viciconsulting.ca — detach or keep?
This is a user decision, not a technical requirement:
- KEEP: leave both old domains attached; they continue to serve as aliases alongside the new domain. root_redirect is enabled on them.
- DETACH: if the user wants only saskstartupsolutions.ca to serve, remove viciconsulting.ca and www.viciconsulting.ca in Deployment Panel → Domains after the new domain is verified and serving.
Recommendation: add + verify the new domain first, confirm it serves over HTTPS, THEN decide whether to detach the old one so there is never a gap in availability. The default *.emergent.host URL always works regardless.
